# Щоденник розробки

Коротка хронологія розробки Metrixify у межах кваліфікаційної роботи. Детальні вимоги — [`технічне-завдання.md`](../технічне-завдання.md), етапи — [план-розробки.md](./план-розробки.md).

## Поточний стан

MVP завершено: бот, веб, AI-пайплайн, кореляції, експорт, виправлення метрик у Telegram. Локально стек піднімається через `npm run app:dev`. Автотести: `npm run test`.

## Що працює

1. Telegram: текст/голос → запис → резюме → метрики → факти профілю
2. Веб: журнал, метрики, профіль, dashboard, кореляції, обліковий запис
3. Вхід через одноразове посилання з бота
4. Двомовний UI (EN/UK) і двомовні назви метрик з AI
5. Кореляції Pearson/Spearman з лагом ±1 день
6. NL-корекції метрик у боті після зведення
7. Експорт JSON/XLSX, видалення даних користувача

## Основні віхи

**Травень 2026 — фундамент.** Розгорнуто монорепо, Docker, Prisma, бот на grammY, перші записи в журнал.

**Етап 3.** Реалізовано вхід без Login Widget — одноразовий токен і httpOnly-сесія.

**Етап 4–5.** Підключено Whisper і резюме через GPT; контекст для моделі стискається в TOON.

**Етап 6–7.** Основний обсяг робіт — метрики: промпт і постобробка на TypeScript (рейтинги, тривалості, cross-day, recap). Далі — resolver для дублікатів ключів.

**Етап 8.** Реалізовано факти профілю з дедуплікацією та фільтрами confidence.

**Етап 9.** Застосовано дизайн за brandbook (лавандова палітра), `vue-i18n`, двомовні поля в БД. Усунуто помилку OpenAI strict schema для bilingual JSON.

**Етап 10.** Математику кореляцій винесено в `analytics-core`; додано heatmap на ECharts. Persona `peanut-rash` для перевірки (r≈0.67, n=30).

**Етап 11.** Додано reprocess запису, виправлення метрик текстом у боті, аудит у `metadata_json`.

**Етап 12 і полірування.** Підготовлено тестовий корпус «синдром-трек», backfill дат з заголовка «День N (дата)». Реалізовано експорт, inline-редагування спостережень, стисле фото на `/start`.

## Усунені інциденти

- Запис зависав на `extracting_metrics` через несумісну JSON Schema (`.optional()` у Zod) — розділено strict і relaxed схеми.
- На Windows `localhost` → IPv6, бот не бачив backend — у `env:setup` нормалізовано на `127.0.0.1`.
- Після рестарту бота старі inline-кнопки викликали падіння — додано `safeAnswerCallbackQuery`.
- Архівні метрики: повторне витягування реактивує рядок за ключем замість створення дубля.
