# План розробки Metrixify

Документ фіксує етапи та критерії готовності дипломного MVP. Повні вимоги — у [`технічне-завдання.md`](../технічне-завдання.md).

## Ключові рішення

| Тема | Рішення |
| --- | --- |
| Менеджер пакетів | npm workspaces |
| Node.js | 22.x |
| UI | англійська за замовчуванням, українська в застосунку |
| Інфраструктура | Docker: PostgreSQL (pgvector) + Redis |
| Запуск dev | `npm run app:dev` |
| Моделі OpenAI | Whisper, `gpt-4o-mini` (витягування), `gpt-4o` (resolver схеми) |
| Вхід у веб | одноразове посилання з бота |
| Бот ↔ API | внутрішній ключ `X-Metrixify-Internal-Key` |
| LLM-вихід | Structured Outputs + Zod |

| № | Назва | Статус |
| --- | --- | --- |
| 0 | Основа монорепо, Docker, health | виконано |

| 2 | Бот: текстові записи, журнал | виконано |
| 3 | Вхід у веб через `/login` | виконано |
| 4 | Транскрипція голосу | виконано |
| 5 | AI-резюме запису | виконано |
| 6 | Витягування метрик | виконано |
| 7 | Узгодження схеми метрик | виконано |
| 8 | Факти профілю | виконано |
| 9 | Дизайн-система, i18n | виконано |
| 10a | Аналітика та кореляції | виконано |
| 10b | Синтетичні persona для перевірки | виконано |

Після MVP додано: експорт даних, редагування спостережень у веб, брендове фото на `/start`.

## Критерії готовності MVP (коротко)

- Текст і голос у Telegram → повний пайплайн до `completed`
- Журнал, метрики, факти профілю, кореляції в UI
- `npm run test` проходить локально з Docker
- Локальний запуск описаний у README
- Документація в `docs/` українською
