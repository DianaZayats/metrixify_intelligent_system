# Локалізація інтерфейсу

Інтерфейс веб-застосунку — англійська за замовчуванням і українська за вибором. Назви метрик і фактів профілю зберігаються двомовно в БД, бо їх генерує модель під час витягування.

## Мова користувача

- Поле `users.locale`: `en` | `uk`
- Веб: перемикач у шапці → `PATCH /api/user/locale`
- Telegram: `/language`
- API: сесія → `Accept-Language` → `?locale=`

## Рядки UI

Файли `apps/frontend/src/locales/`, `vue-i18n`. Статуси обробки, типи фактів — ключі `enums.*`.

## Що двомовне в БД

| Поле | Двомовне |
| --- | --- |
| Заголовки/опис/теги метрик | `*_i18n` JSON |
| Значення фактів профілю | `value_i18n` |
| `summary_text` | ні — мова запису |
| `evidence_text`, сирий текст | ні |
| `key`, коди enum | латиниця |

Якщо в старому рядку `titleI18n` порожній — при наступному витягуванні з тим самим ключем спрацьовує `syncDefinitionDisplayFromCandidate()`. Інакше потрібен reprocess або PATCH.

## Примітка на майбутнє

Двопрохідна схема (extract EN → translate UK) може бути дешевшою — наразі використовується один bilingual-прохід у промпті.
